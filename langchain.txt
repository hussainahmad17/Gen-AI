Gen AI using LangChain:

1. Why we need LangChain:
Before LangChain, LLMs just generated text; they didn't have access to our specific data. However, we need to use LLMs based on our own data, logic, memory, and specific needs, but there wasn't a framework that allowed us to customize LLMs in this way. This is where LangChain comes in.
LangChain is a framework that connects LLMs with our data and provides built-in tools, libraries, packages, and features to use LLMs according to our needs.

2. ------------------------- Components of LangChain -----------------------------------
Models
Prompts
Chains
Indexes
Memory
Agents

Models:
Models are the interfaces that standardize the way of interacting (communicating) with AI models.

Prompts:
The Prompts component is used for creating dynamic, reusable prompts using prompt templates.

Chains:
Chains are used to create pipelines. The output of one LLM automatically becomes the input of another LLM.

Indexes:
Indexes are used to connect LLMs with external knowledge.

It includes:
-> Document Loaders: Load documents from where they are stored (e.g., S3).
-> Text Splitters: Divide text into chunks to generate embeddings.
-> Vector Store: Store the generated embeddings.
-> Retrievers: Create embeddings of the user query and perform a semantic search in the Vector Store. The result and user query are then passed to the LLM to generate the final result.

Memory:
Used to store chat history and remember past interactions.
Types:
-> ConversationBufferMemory: Stores all past chats and passes the history + query to the LLM to generate an answer.
-> ConversationBufferWindowMemory: Stores the last 'n' number of chats and then passes that history + query to the LLM to generate an answer.
-> ConversationSummaryMemory: Summarizes all past chats and then passes that summary + query to the LLM.

Agents: Agents combine LLMs + Tools + Custom Logic + Memory.

3. ----------------------- Explanation of LangChain Components -------------------------

Models:
There are two types of models:
-> Language Models: Take text, generate text.
-> Embedding Models: Take text, generate vectors.

In Language models, there are LLMs and Chat models. LLM API requests are stateless. Chat models are fine-tuned for conversations.
There are closed-source models like Claude and GPT, and open-source models available on Hugging Face.
We can interact with all these models via APIs. For Hugging Face, an access token is required.

Prompts:
This component is used to create dynamic and reusable prompts. There are three types of messages:
-> System Messages (AI instructions)
-> Human Messages (Human input)
-> AI Messages (AI output)

Chains:
Pipelines where the output of one runnable becomes the input of another runnable automatically.
Example: chain = prompt | model | Parser

----------------------- Structured Output ---------------------------------------------------

For data storage in a database, we need structured data from chat models.
For chat models that natively support structured output, we can use the method: `with_structured_output` with:
-> TypedDict: Use the "typing" library and import the TypedDict class. Define a schema (class) which inherits from TypedDict.
-> Pydantic: From Pydantic, import BaseModel. Define a schema (class) which inherits from BaseModel. Use "Field" to provide descriptions for the required fields.

For chat models that are unable to generate structured output by default, we can use:
-> Output Parsers

----------------------- Retrievers -------------------------------------------------------------

Multi Query Retrievers:
These are used when a user query is ambiguous.
They generate multiple versions of the base (user) query that are not ambiguous.
Then, they retrieve relevant documents for all those generated queries, combine them, and use them to generate the final answer.
